# 残高不整合の正確な分析

## 🔍 検出された残高不整合（実際の保有量 vs Redis記録）

### 1️⃣ LINK/JPY (BOLLINGER_BANDS) - 🚨 緊急
- **実残高**: 0 LINK（取引所に保有なし）
- **Redisポジション**: 0.0162 LINK 記録
- **問題**: 既に売却済みなのにRedisにポジションが残存
- **原因推定**: ストップロス実行成功後、Redis更新失敗

### 2️⃣ GALA/JPY (OSCILLATOR) - ⚠️ 重要
- **実残高**: 3.1458 GALA（使用中）/ 95.7226 GALA（総計）
- **Redisポジション**: 34.3695 GALA 記録
- **問題**: Redisの記録が実際の使用中残高の11倍
- **原因推定**: 大量の部分決済がRedisに未反映

### 3️⃣ XRP/JPY (MUTUAL_INFO) - 軽微
- **実残高**: 0.6969 XRP（使用中）
- **Redisポジション**: 0.7133 XRP 記録
- **乖離**: 0.0164 XRP（2.35%）
- **原因推定**: 小さな約定差、許容範囲

### 4️⃣ XLM/JPY (RSI) - 中程度
- **実残高**: 8.8554 XLM（使用中）
- **Redisポジション**: 7.5145 XLM 記録
- **問題**: 実残高の方が多い（他の購入が未記録）
- **原因推定**: 手動購入または他戦略の取引

### 5️⃣ APE/JPY (OSCILLATOR) - 中程度
- **実残高**: 5.2437 APE（使用中）
- **Redisポジション**: 1.8634 APE 記録
- **問題**: 実残高が記録の3倍近い
- **原因推定**: 手動購入または記録失敗

## 📊 不整合パターン分析

### A. **ゾンビポジション**（実残高ゼロ、記録あり）
- **該当**: LINK/JPY
- **危険度**: 🚨 最高
- **影響**: ストップロス再実行で失敗エラー
- **対策**: 即座にRedis削除

### B. **記録過多**（実残高 < 記録）
- **該当**: GALA/JPY, XRP/JPY
- **危険度**: ⚠️ 高
- **影響**: 存在しない分の売却試行でエラー
- **対策**: 実残高に合わせて記録調整

### C. **記録不足**（実残高 > 記録）
- **該当**: XLM/JPY, APE/JPY
- **危険度**: 🔶 中
- **影響**: リスク管理対象外の保有
- **対策**: 未記録分のポジション追加

## 🔧 根本原因

### 1. システム的原因
- **非同期処理**: 売却実行とRedis更新の間隔
- **エラーハンドリング**: Redis保存失敗時の不完全な処理
- **部分約定**: 予期しない部分約定への対応不足

### 2. 運用的原因
- **手動取引**: システム外での直接取引
- **他戦略競合**: 同一通貨ペアでの複数戦略競合
- **管理ツール**: 管理者による手動調整

### 3. 外部要因
- **取引所仕様**: bitbank API制限
- **ネットワーク**: Redis接続不安定
- **タイミング**: 高頻度取引時の競合状態

## 🚨 即座に対応が必要な案件

### LINK/JPY ゾンビポジション削除
```bash
docker compose exec redis redis-cli DEL "position:bitbank:LINK/JPY:BOLLINGER_BANDS:46807587451"
```

### GALA/JPY ポジション量修正
```bash
# 現在: 34.3695 → 実残高: 3.1458 に調整
docker compose exec redis redis-cli HSET "position:bitbank:GALA/JPY:OSCILLATOR:46810939296" amount "3.1458"
```
